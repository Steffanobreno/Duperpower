# Fino Onda 1 (boletim, preencher o buraco, indicadores, "Agendado com Fino") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the four zero-cost features of Wave 1: the post-groom report card, "fill the gap", the KPI panel and the "Booked with Fino" footer, plus the shared "send from my phone" buttons.

**Architecture:** Same patterns as the rest of the app: Postgres migrations in `db/migrations`, data functions in `src/lib/data/*` that take a `StaffContext` and filter by `business_id`, server components and server actions in `src/app/(owner)`, public pages that look up a random token, and client messages through `src/lib/messaging.ts`. Nothing new costs money: WhatsApp/SMS open on the groomer's phone, email goes out the way it already does, and distances are straight lines.

**Tech Stack:** Next.js 16.4 (App Router; read `node_modules/next/dist/docs/` before writing routes, per `AGENTS.md`), React 19.3, Tailwind v4, `postgres` (postgres.js), Playwright e2e scripts in `tests/e2e/*.mjs`.

**Spec:** `docs/superpowers/specs/2026-11-07-fino-vantagem-competitiva-design.md`, section 5. Read it before each task.

## Global Constraints

- Every query filters by `staff.businessId`. Public pages are reached only by a random token (`/^[0-9a-f]{32}$/`); a wrong token → `notFound()`.
- Owner screens: every visible string goes through `t("…")`, `tr("…")` or `msg("…")` (in English), so `tests/owner-phrases.mjs` and `scripts/owner-keys.mjs` find it.
- Client pages (`/g/[token]`, `ClientShell`): every string through `t("…")`, translated in all 20 files `src/lib/i18n/messages/*.ts` in the same task. `node tests/i18n-check.mjs` must pass.
- Message templates: English default bodies in `src/lib/new-business.ts` `templates`. Each migration that adds a trigger also inserts its template for the businesses that already exist and widens `message_templates_trigger_check`.
- No new npm dependency, and no paid API call in any new code path.
- Money uses `money()`; dates use `staff.timezone` (`format.ts`); distances use miles or km by the business's region (`staff.region`).
- Commits: one per task, message in English, ending with the two attribution lines the session gives.
- Nothing goes to `master`. Work and push on `claude/clever-clarke-3ukcxg`.

2. **Client with no phone, or SMS opted out:** WhatsApp shows; SMS is hidden when opted out; with no phone, neither shows and nothing crashes. → assertion in Task 1.
3. **Day with no working hours** (day off, or closed day) **in "fill the gap":** no gaps and no Today card, never a crash. → assertion in Task 6.

**Interfaces:**
- Produces:
  ```ts
  export type Kpi = { key: "revenue" | "visits" | "avg_ticket" | "return_rate" | "occupancy" | "no_shows" | "overdue" | "reports_sent" | "offers_booked"; value: number; previous: number | null; unit: "money" | "count" | "percent" };
  export async function monthKpis(staff: StaffContext, today: string): Promise<Kpi[]>;
  export async function todayKpis(staff: StaffContext, today: string): Promise<Kpi[]>; // revenue (month), occupancy (this week Mon–Sun), overdue
  ```
- Period: the 1st of `today`'s month → `today`, in `staff.timezone`. `previous`: the same day-count window last month.
- Definitions (cents and counts; `LIVE` as in `reports.ts`):
  - **revenue:** `sum(payments.amount_cents)` by `received_at` in the window (tips excluded, as in Reports "collected").
  - **visits:** appointments `completed` with `start_at` in the window.
  - **avg_ticket:** revenue ÷ visits, rounded; 0 when visits = 0.
  - **return_rate:** among distinct clients with a completed visit in the last 60 days, the % that have a live visit with `start_at > now()`. `previous: null`.
  - **occupancy:** booked minutes of live appointments ÷ working minutes from `working_hours` for each day of the window, for that staff member, excluding closed days. Percent, 0 when the denominator is 0.
  - **no_shows:** `no_show` + `cancelled` with `start_at` in the window.
  - **overdue:** count of clients that would be "due" for `today` by the Task 6 rule (reuse its SQL fragment; export it from `fill-gap.ts` as `overdueClientIdsSql`, or a small `overdueCount(staff, date)`). `previous: null`.
  - **reports_sent:** `report_sent_at` in the window.
  - **offers_booked:** `fill_offers` in the window whose client got a live appointment created after `sent_at` for that `day`.
- `<KpiTiles kpis t />`:
  - grid of tiles: label, value (`money()` / count / `n%`), and a change line:
    - `t("▲ {n}% vs last month")` or `t("▼ {n}% vs last month")` when `previous > 0`;
    - `t("new")` when `previous === 0 && value > 0`;
    - nothing when `previous` is null.
  - The "overdue" tile links to `/fill/<today>`.
  - Pure markup: no chart library, no client JS.
